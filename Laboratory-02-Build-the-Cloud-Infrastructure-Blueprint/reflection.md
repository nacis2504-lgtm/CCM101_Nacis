# Mission Reflection

## 1. Which cloud infrastructure component do you think is the most important? Why?

All components of cloud infrastructure are vital, but it appears that **computing resources**, without any doubts, represent the most basic part of the whole process. The lack of processing capabilities makes the whole storage and networking systems senseless. Computing resources are connected with application performance, scalability, and economic efficiency. If an organization has the chance to provide, improve, or optimize virtual machines, containers, and serverless functions, it will be able to render the necessary services. Furthermore, computing-related decisions can affect the storage and networking systems without any doubts, which renders them the main basis of all other resources.

## 2. How does Linux support cloud computing?

There are several significant reasons why Linux is considered the pillar of current cloud computing. First of all, it is open-source and absolutely free, which helps minimize the cost of cloud infrastructure for the service provider. Another reason is that Linux is known to ensure a lot of stability, reliability, and unbeatable performance capacities in virtualized environments. In addition, the command line of Linux is recognized as a great tool for automation, which is essential for infrastructure as code and DevOps practices in general. Moreover, with the help of Linux, one can use containerization technologies such as Docker and Kubernetes, which form the basis of modern cloud applications. Finally, it would be impossible to operate the cloud infrastructure properly without the vast diversity of Linux tools and utilities.

## 3. Why is technical documentation important before deploying infrastructure?

Technical documentation is important since it provides the foundation for effective infrastructure implementation. Good technical documentation ensures that misconfigurations are avoided, deployments are smoother, and consistency of environments is achieved. Documentation also helps spread knowledge within teams, making collaboration easier while reducing the bus-factor risks. In case issues occur, documentation serves as a guide when troubleshooting and searching for the root causes. Moreover, it proves necessary for compliance and proper governance of operations. Finally, good documentation makes the process of integrating new employees easier and serves as the history of decisions made in relation to infrastructure.
